Browser Storage & Workers

  1. 1. Browser Storage Comparison

    Storage Capacity Lifetime Sent with HTTP Requests? Best Use Case
    localStorage ~5MB - 10MB Persistent until explicitly deleted No User UI preferences, themes, non-sensitive cached data
    sessionStorage ~5MB Tab/Session lifetime (cleared on tab close) No Multi-step form wizards, temporary single-tab state
    Cookies ~4KB Manually set via Expires / Max-Age Yes (Sent automatically in request headers) Auth session tokens, tracking IDs
    IndexedDB >250MB (Gigabytes) Persistent No Large structured data, files, offline database storage

  2. 2. Cookie Security Flags (Crucial for Interviews)

    - HttpOnly: Prevents client-side scripts from reading the cookie via document.cookie. Crucial defense against Cross-Site Scripting (XSS) session hijacking.
    - Secure: Ensures the cookie is only transmitted over encrypted HTTPS connections, preventing Man-in-the-Middle (MitM) attacks.
    - SameSite: Controls whether cookies are sent with cross-site requests to defend against Cross-Site Request Forgery (CSRF):
      • Strict: Cookie is never sent on cross-site requests.
      • Lax (Default): Sent on top-level safe navigations (like clicking an external link), but omitted on cross-site subrequests (images, POST forms).
      • None: Sent on all cross-site requests (requires Secure).

  3. 3. Web Workers vs Service Workers

    - Web Workers: Create background OS-level threads to execute heavy computational tasks (crypto, video/image processing, large calculations) without freezing the main UI thread. They communicate with the main thread via postMessage() and onmessage.
    - Service Workers: Act as an asynchronous programmable network proxy between the browser and the network. They enable Progressive Web App (PWA) features: offline asset caching, background data sync, and push notifications.
